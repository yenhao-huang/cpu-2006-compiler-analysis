第一個發現：O3 比研究用 pipeline 快 +19.9%

讀法

每列為 default<O3> 相對原研究 full 的速度變化，確認階段 12 對幾何平均。

重點

  • HMMER +214.0%（約 3.1 倍；圖中截斷）
  • Cactus +48.3%、Tonto +21.3%、Xalan +19.2%
  • 只有 bzip2（-2.4%）與 WRF（-2.1%）是 full 較快

skill 其他等級

  • -O2 與 O3 差距多在 ±3% 內
  • -Os .text −4% 至 −31%，但 Xalan -9.3%、Cactus -13.1%

  • 原研究 pipeline 完全沒有 GVN：O3 有數千筆冗餘消除，與 O3 整體快 20% 一致。
  • Tonto 向量化：x86-64 (SSE2) 成本模型讓多數 Fortran 迴圈不值得向量化；改 AVX2 後成功數增加約 5 倍。
  • LTO 每項都 inline 更多，且刪除未被呼叫的函式庫程式碼（右圖）。

含 FMA無 FMA

解讀

  • WRF 的增益來自 AVX2 寬度，關 FMA 仍保留
  • Tonto 的增益全來自 FMA；不能逐位元組相同就不採用
  • skill 未提醒此風險

10

skill 評估

有用

  • 最佳化等級、LTO、目標 ISA 三個方向找出全部主要增益
  • Optimization Remarks 直接指出 GVN 缺席、Tonto 向量化與 LTO inlining
  • Inlining／SLP 的概念說明對選 knob 有幫助

不足或與工具鏈不符

  • opt -instcombine in.ll（Alive2 範例）在 LLVM 19 失敗，需 -passes=
  • opt -stats 在兩個 Debian release 工具鏈無輸出
  • 未說明 new PM 下如何關 SLP：-vectorize-slp=false 無效，需 -slp-threshold
  • 未提醒改 ISA 會讓 contract 浮點融合成 FMA
  • 沒有 PGO、ThinLTO 實際流程；大段內容偏向 pass 開發
11

限制與下一步

限制

  • 共用主機、未關 turbo；同檔控制單對仍可偏差 10% 以上，2% 以下不作結論
  • repo 內程式與固定輸入，不是官方 SPEC 分數；454.calculix 實為 SPOOLES 元件
  • 只在 i7-14700K 驗證；alderlake ISA 執行檔需要 AVX2
  • tuned 在同一輸入上選出，已獨立重測，換輸入或機器仍需重驗

下一步

  • PGO（instrumented / sample-based）與 ThinLTO
  • 把 GVN 加入研究用 pipeline，重做消融以分離其貢獻
  • 以 Flang -O2/-O3 前端重產 Fortran IR，比較 FIR 層最佳化
  • 換輸入（SPEC train/ref）與另一台機器驗證 tuned 設定
